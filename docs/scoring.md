# Правила оценки

Все награды и оценки вычисляет сервер. Код: `backend/app/gamification/` (правила), `backend/app/services/rewards.py`
(начисление), `backend/app/services/competency.py` (компетенции и рекомендации).

## Две игровые шкалы

«Лояльность пассажиров» и «Рейтинг безопасности» — значения 0–100 внутри одной попытки. Начальные значения задаёт сценарий
(`initial`, по умолчанию 50/50), каждое решение прибавляет `effects`, после чего шкала ограничивается диапазоном 0–100.
В логе и разборе хранится **фактическое** изменение после ограничения.

## Результат рейса и опыт

- **Результат рейса** = (итоговая лояльность + итоговая безопасность) / 2, половины округляются вверх. Диапазон 0–100.
- **Опыт (XP)** = сумма лучших результатов сотрудника по каждому сценарию.
- Завершённая попытка добавляет `max(0, результат − прежний лучший результат в этом сценарии)`.

Поэтому бесконечное повторение одного сценария опыт не накручивает: повтор с тем же или худшим результатом даёт 0,
лучший — только разницу. Пример: 48 → 38 → 58 даёт +48, +0, +10; опыт по сценарию — 58.

**Ровно один раз.** Награды начисляются в той же транзакции, что и финальный шаг попытки (выбор, тайм-аут или тайм-аут,
применённый при восстановлении страницы). Шаг фиксируется один раз: блокировка строки попытки и уникальный индекс
`(attempt_id, step)`. Начисление дополнительно сериализуется блокировкой строки сотрудника.

## Уровни

| Уровень | Название | Опыт от |
|---|---|---|
| 1 | Стажёр | 0 |
| 2 | Проводник | 50 |
| 3 | Опытный проводник | 120 |
| 4 | Старший проводник | 200 |
| 5 | Наставник | 300 |

Повышение уровня создаёт внутреннее уведомление.

## Достижения

Идентификаторы стабильны; тексты не участвуют в проверке.

| ID | Название | Условие |
|---|---|---|
| `first_trip` | Первый рейс | первое завершение любого сценария (правило сервера) |
| `diplomat` | Дипломат | условие `awards` в сценарии: в «Месте у окна» — спокойный подход и тактичное объяснение без резкости, игнорирования и пустого обещания; в демо — снятие конфликта альтернативным местом |
| `safe_passage` | Безопасный проход | условие `awards`: флаг `aisle_cleared_in_time`, который ставят только варианты, убирающие чемодан до истечения таймера |

Условия `awards` — декларативные (флаги и пороги шкал) и проверяются на итоговом состоянии попытки. Каждое достижение
выдаётся сотруднику один раз (уникальный индекс).

## Рейтинг

Рейтинг проводников по опыту: бригада (та же бригада и депо), депо, компания. Одинаковый опыт — одинаковое место.
Отдаются только отображаемые поля: место, имя, бригада, депо, уровень, опыт, число пройденных сценариев, признаки
«это вы» и «синтетические данные». Методисты в рейтинг не входят.

## Компетенции

Компетенции отделены от опыта и от двух шкал:

| ID | Название | Что означает |
|---|---|---|
| `communication` | Коммуникация | тон, деэскалация, работа с обеими сторонами |
| `safety` | Безопасность | своевременное устранение угроз |
| `first_aid` | Первая помощь | оценивается в сценарии «Пассажиру стало плохо»; без его прохождения — «нет данных» |
| `stress_resistance` | Стрессоустойчивость | учебный показатель качества действий в шагах с таймером; не психологическая оценка |

**Правила оценки в данных.** Вариант ответа и исход тайм-аута содержат `assessment`, например
`{"communication": 2, "safety": 1}` (целые 0–10).

**Расчёт шага.** Для каждой компетенции, упомянутой у доступных игроку вариантов:
`максимум = наибольший балл среди видимых вариантов`, `набрано = балл выбранного варианта` (для тайм-аута — балл
исхода тайм-аута, обычно 0). Скрытые условием варианты не учитываются, поэтому максимум честный. Шаги с максимумом 0
для компетенции не оцениваются.

**Итог попытки** — суммы набранного и максимума по шагам.

**Профиль.** Для каждого сценария берётся **последнее завершённое** прохождение; по всем сценариям суммируются набранные
и максимальные баллы; оценка = набрано / максимум. Повторное прохождение заменяет вклад сценария, а не добавляет его.
Если максимум 0 — «нет данных».

**Слабая компетенция** — оценённая компетенция с наименьшим процентом ниже 100%. Если все оценённые решения верны,
слабой нет.

## Рекомендации

Правила по тегам опубликованных сценариев (теги-компетенции задаются в карточке сценария):

1. Нет завершённых попыток → первый опубликованный сценарий («Первый рейс»).
2. Есть слабая компетенция и непройденный сценарий с её тегом → он, с причиной «Слабая компетенция — X (N%)».
3. Есть непройденный сценарий → он.
4. Всё пройдено → повтор сценария, где по слабой компетенции худший результат, с целью «больше e из m баллов»;
   если слабой нет — повтор сценария с наименьшим лучшим результатом с целью превзойти его.
5. Нет опубликованных сценариев → карточки нет.
