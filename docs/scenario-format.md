# Формат сценария (v2)

Сценарий — JSON-граф узлов. Встроенные сценарии лежат в `backend/app/scenarios/data/*.json`
(`{"title", "description", "tags", "graph"}`) и загружаются `python -m app.seed`; новые создаются в редакторе методиста,
импортом JSON или через `POST /scenarios`. Все тексты, числа, объяснения, оценки компетенций и визуальные метаданные
хранятся в данных — код движка и интерфейса от конкретного сценария не зависит.

Граф проверяется валидатором (`app/scenarios/validator.py`) до сохранения; ошибка — HTTP 422 со списком
всех проблем и путём к каждой. Поэтому во время прохождения движок доверяет форме графа.

Сценарии формата v1 (без `initial`, `flags`, `transitions`) продолжают работать: это частный случай v2.

## Пример

Сокращённый фрагмент «Места у окна» (полная версия — `backend/app/scenarios/data/window_seat.json`):

```json
{
  "initial": {"loyalty": 60, "safety": 80},
  "flags": {"was_rude": false, "aisle_cleared": false},
  "start_node": "start",
  "nodes": {
    "start": {
      "text": "К вам подходит девушка: «В моём кресле 7А сидит мужчина…»",
      "debrief": "Лучший первый шаг — спокойно выслушать обе стороны.",
      "choices": [
        {"id": "calm", "text": "Спокойно выяснить, что произошло",
         "effects": {"loyalty": 5}, "explanation": "Спокойный тон снижает напряжение.",
         "next_node": "suitcase"},
        {"id": "order", "text": "Строго потребовать освободить место",
         "effects": {"loyalty": -10}, "set_flags": {"was_rude": true},
         "explanation": "Приказ до проверки фактов звучит как обвинение.",
         "next_node": "suitcase"}
      ]
    },
    "suitcase": {
      "text": "Чемодан перегораживает проход — решать нужно сейчас.",
      "timer_seconds": 20,
      "timeout": {"effects": {"loyalty": -5, "safety": -20},
                  "explanation": "Пассажирка споткнулась о чемодан.", "next_node": "trip"},
      "choices": [
        {"id": "stow_together", "text": "Вместе убрать чемодан",
         "effects": {"loyalty": 5, "safety": 10}, "set_flags": {"aisle_cleared": true},
         "next_node": "resolution"}
      ]
    },
    "resolution": {
      "text": "Мужчина собирается перейти в свой вагон.",
      "choices": [
        {"id": "escort", "text": "Проводить мужчину", "effects": {"loyalty": 5},
         "transitions": [
           {"condition": {"not": {"flag": "aisle_cleared"}}, "next_node": "aisle"},
           {"condition": {"any": [{"flag": "was_rude"},
                                  {"scale": "loyalty", "op": "<", "value": 70}]},
            "next_node": "end_dissatisfied"},
           {"next_node": "end_calm"}
         ]}
      ]
    },
    "end_calm": {"text": "…", "is_ending": true, "outcome": "calm_resolution",
                 "ending_summary": "Спокойное разрешение: …"}
  }
}
```

## Поля

### Граф

| поле | обяз. | описание |
|---|---|---|
| `start_node` | да | id первого узла |
| `nodes` | да | объект `id → узел`, непустой |
| `initial` | нет | начальные шкалы `{"loyalty": 0..100, "safety": 0..100}`; по умолчанию 50/50 |
| `flags` | нет | объявление флагов попытки: `имя → значение по умолчанию (true/false)` |
| `awards` | нет | достижения за сценарий: `[{"achievement": "diplomat", "when": условие}]`, проверяются на итоговом состоянии |
| `visual` | нет | персонажи сцены: `{"characters": {"man": {"name", "figure": man/woman/passenger, "pose": sitting/standing, "position": left/center/right}}}` |

Теги (`tags` рядом с `title`) — список строк; идентификаторы компетенций среди них (`communication`, `safety`,
`first_aid`, `stress_resistance`) используются в рекомендациях.

### Узел-шаг

| поле | обяз. | описание |
|---|---|---|
| `text` | да | описание ситуации |
| `choices` | да | непустой список вариантов; хотя бы один — без `condition` |
| `timer_seconds` | нет | целое 5..600; отсутствует или `null` — шаг без таймера |
| `timeout` | если есть таймер | исход при истечении времени (см. «Исход»); без таймера запрещён |
| `debrief` | нет | урок шага для разбора: как было правильно поступить |
| `visual` | нет | сцена узла: `speaker`, `moods` `[{"character", "mood", "when"?}]`, `props` `[{"id": suitcase/spill, "when"?}]` |

### Вариант = исход + отображение

| поле | обяз. | описание |
|---|---|---|
| `id` | да | уникален внутри узла |
| `text` | да | текст кнопки |
| `condition` | нет | вариант показан и принимается, только если условие истинно (проверяется **до** применения эффектов) |
| + поля исхода | | см. ниже |

### Исход (вариант или `timeout`)

| поле | обяз. | описание |
|---|---|---|
| `effects` | нет | `{"loyalty": int, "safety": int}`, каждое −100..100 |
| `set_flags` | нет | `{"флаг": true/false}`; флаг должен быть объявлен в `graph.flags` |
| `explanation` | нет | почему решение так влияет на шкалы (показывается в результате) |
| `assessment` | нет | оценка решения по компетенциям: `{"communication": 2, "safety": 1}`, целые 0–10 (см. [scoring.md](scoring.md)) |
| `next_node` | одно из двух | безусловный переход |
| `transitions` | одно из двух | список `{"condition"?, "next_node"}`: берётся первый, чьё условие истинно; последний — **без** условия (по умолчанию) |

### Финал

`{"text", "is_ending": true, "ending_summary", "outcome"?, "visual"?}` — без вариантов и таймера. `outcome` —
машинный код финала для интерфейса и аналитики (`calm_resolution`, `resolved_with_dissatisfaction`, `escalated_to_senior`).

## Визуальные метаданные

Необязательны: без них сцена показывает пустой вагон. Сервер отдаёт клиенту только вычисленный результат —
присутствующих персонажей с настроением и видимые предметы, — но не условия. Настроение без правила следует шкале
лояльности (≥75 доволен, ≥55 спокоен, ≥40 встревожен, ≥25 расстроен, иначе раздражён). Логика интерфейса не
привязана к идентификаторам узлов.

## Условия

Декларативный JSON, интерпретируется `app/scenarios/conditions.py`; `eval` и выражения-строки не используются.
В каждом объекте ровно одна форма:

| форма | смысл |
|---|---|
| `{"flag": "was_rude"}` | флаг истинен |
| `{"scale": "loyalty", "op": ">=", "value": 70}` | сравнение шкалы; `op`: `>=`, `>`, `<=`, `<`, `==`, `!=`; `value` 0..100 |
| `{"all": [усл, …]}` | все истинны |
| `{"any": [усл, …]}` | хотя бы одно истинно |
| `{"not": усл}` | отрицание |
| `{"min_loyalty": 40}`, `{"min_safety": 40}` | сокращение v1 для `scale >= value` |

Глубина вложенности — не более 8 уровней.

## Порядок применения шага

Выполняется в одной транзакции под блокировкой строки попытки (`app/scenarios/engine.py`, `app/services/attempts.py`):

1. Попытка должна быть `in_progress`, а `expected_step` из запроса — равен `attempt.step`; иначе 409.
2. Если у узла есть таймер и `now >= node_shown_at + timer_seconds` — применяется `timeout` узла,
   присланный `choice_id` игнорируется. Иначе:
   - `choice_id: null` → 409 `timer_not_expired` (или 422 `choice_required`, если таймера нет);
   - вариант ищется среди **видимых**: его `condition` проверяется на состоянии **до** шага;
     скрытый и несуществующий вариант дают одинаковую ошибку 422 `choice_not_available`.
3. Для каждой компетенции записывается «набрано / максимум» по видимым вариантам (см. [scoring.md](scoring.md)).
   `effects` прибавляются к шкалам, каждая шкала ограничивается диапазоном 0..100.
   В лог пишется фактическое изменение после ограничения.
4. Применяются `set_flags`.
5. Выбирается следующий узел: `next_node` или первый подходящий элемент `transitions`;
   условия переходов проверяются на состоянии **после** шагов 3–4.
6. `step += 1`, `node_shown_at = now` (таймер нового узла стартует сейчас). Финальный узел завершает попытку,
   и в той же транзакции начисляются результат, опыт, достижения и уведомления.
7. Пишется строка лога `(attempt_id, step)`; уникальный индекс не даёт записать один шаг дважды —
   проигравший параллельный запрос откатывается целиком и получает 409 `step_mismatch`.

Просроченный таймер догоняется и при чтении: `GET /attempts/{id}` применяет `timeout` (шаги 3–7), если дедлайн
прошёл, пока клиент был офлайн.

## Снимок сценария

При старте попытка копирует граф, название и версию сценария. Движок читает только снимок, поэтому публикация новой
версии в редакторе не влияет на начатые прохождения. Черновик редактора (`scenarios.draft`) не виден проводникам;
сценарий, ни разу не опубликованный (версия 0), нельзя начать. Встроенный сценарий, переопубликованный из редактора,
seed больше не перезаписывает.

## Что проверяет валидатор

- типы и обязательность всех полей выше, неизвестные поля (опечатки вроде `next_nod`);
- уникальность `id` вариантов внутри узла, диапазоны таймера, эффектов, начальных шкал и порогов;
- `timeout` ⇔ `timer_seconds`; ровно одно из `next_node` / `transitions`; последний переход без условия,
  промежуточные — с условием;
- объявленность всех флагов в `set_flags` и условиях; формы условий и глубина вложенности;
- существование всех целевых узлов; достижимость каждого узла от `start_node`;
  наличие хотя бы одного финала и пути к финалу из каждого достижимого узла;
- хотя бы один вариант без условия в каждом узле — игрок никогда не остаётся без выбора;
- оценки компетенций (известные компетенции, 0–10), условия достижений, визуальные метаданные (объявленные персонажи,
  допустимые настроения и предметы, условия).

Анализ путей игнорирует условия (считает все рёбра). Это безопасно: в каждом узле есть безусловный вариант,
а у каждого списка переходов — переход по умолчанию.
