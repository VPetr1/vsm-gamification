# Рейс 400 — тренажёр проводника ВСМ

Геймифицированный тренажёр для проводников высокоскоростной магистрали (хакатон Московского транспорта).
Проводник от первого лица проходит рабочие ситуации в вагоне: принимает решения, в критических шагах — под таймером,
видит реакцию пассажиров и изменение двух шкал («лояльность пассажиров» и «рейтинг безопасности»), получает подробный
разбор, опыт, достижения, оценки компетенций и рекомендации. Методист редактирует сценарии без программирования.

Люди и ситуации вымышлены. Сценарии опираются на материалы кейса — примеры ситуаций взаимодействия поездного персонала с
пассажирами и ролевую модель «признать — обозначить правило — предложить решение — заверить» — и не заменяют действующие регламенты.

## Возможности

- **Движок сценариев** — нелинейный JSON-граф: условия на флагах и порогах шкал, условные переходы, таймеры с серверным
  дедлайном, тайм-аут как отдельная ветка, снимок сценария в каждой попытке.
- **Прохождение** — сцена вагона с персонажами, их настроение меняется по ходу; таймер только на критических шагах;
  восстановление после перезагрузки; защита от двойного клика и параллельных запросов.
- **Разбор** — каждое решение, фактические изменения шкал, объяснение, «как лучше», баллы компетенций.
- **Геймификация** — результат рейса, опыт (только за улучшение лучшего результата), уровни, достижения «Первый рейс»,
  «Дипломат», «Безопасный проход», история, рейтинг по бригаде / депо / компании, внутренние уведомления.
- **Компетенции** — коммуникация, безопасность, первая помощь, стрессоустойчивость как учебный показатель действий
  под таймером; «нет данных», пока компетенция не оценена; слабая компетенция и рекомендация с причиной.
- **Редактор методиста** — черновик, формы узлов и вариантов, конструктор условий, таймеры, оценки, визуальные
  метаданные, проверка с путями к ошибкам, публикация новой версии, импорт и экспорт JSON.
- **Доступ** — демо-аккаунты, серверные сессии, роли «проводник» и «методист», блокировка входа после 5 неверных паролей.
- **Интеграция с HR/LMS** — `/integrations/progress` и `/integrations/attempts` по ключу `X-API-Key` (включается
  переменной `INTEGRATION_API_KEY`), с инкрементальной выгрузкой завершённых попыток.

Сценарии:
- «Место у окна» — пассажир не на своём месте и ручная кладь в проходе (13 узлов, 3 финала; ситуации кейса № 8, 13, 14);
- «Пассажиру стало плохо» — медицинский случай с критическим шагом под таймером (9 узлов, 3 финала; ситуации № 19, 28, 29);
- «Конфликт из-за откинутого кресла» — короткий демо-сценарий.

## Быстрый старт (Docker)

Нужен Docker Desktop (Windows, macOS) или Docker Engine с Compose v2.

```bash
git clone https://github.com/VPetr1/vsm-gamification.git
cd vsm-gamification
docker compose up --build
```

- Приложение: <http://localhost:8080>
- Документация API (Swagger): <http://localhost:8000/docs>

При старте бэкенд применяет миграции и заполняет демо-данные; повторный запуск ничего не дублирует. Данные хранятся в
томе Docker и переживают перезапуск. Полная очистка: `docker compose down -v`.

Настройки — в `.env` (необязательно, у всех значений есть значения по умолчанию):

```bash
cp .env.example .env
```

В Windows PowerShell: `Copy-Item .env.example .env`. Если порт 8080 или 8000 занят, поменяйте `FRONTEND_PORT` или
`BACKEND_PORT` в `.env`. PostgreSQL наружу не публикуется, поэтому локальная база на порту 5432 не мешает.

## Разработка без Docker

Бэкенд (Python 3.12, нужен PostgreSQL):

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export DATABASE_URL=postgresql://vsm:vsm@localhost:5432/vsm
python -m app.db_upgrade && python -m app.seed
uvicorn app.main:app --reload --port 8000
```

Фронтенд (Node.js 20+), Vite проксирует `/api` на `localhost:8000`:

```bash
cd frontend
npm install
npm run dev
```

Приложение откроется на <http://localhost:5173>.

## Тесты

```bash
cd backend && python -m pytest -q
cd frontend && npm test && npm run build
```

Бэкенд-тесты работают на SQLite в памяти: время запроса подменяется, поэтому таймеры проверяются точно на границе.
Покрыты движок, валидатор, тайм-ауты и восстановление, двойная отправка, авторизация и границы доступа, награды ровно
один раз, опыт без накрутки, компетенции и рекомендации, редактор и версии, миграции. Тест настоящей гонки запросов
запускается только на отдельной базе PostgreSQL, имя которой оканчивается на `_test`; её схема пересоздаётся:

```bash
TEST_DATABASE_URL=postgresql://vsm:vsm@localhost:5432/vsm_test python -m pytest tests/test_concurrency_pg.py
```

## Безопасность и данные

- В демо только вымышленные сотрудники и сценарии; реальных персональных данных нет (152-ФЗ). Синтетические результаты
  помечены в интерфейсе.
- Пароли хранятся как PBKDF2-SHA256; сессия — случайный токен в cookie `HttpOnly; SameSite=Lax`, в базе только его
  SHA-256; выход удаляет сессию.
- Личность и роль берутся из сессии: чужие попытки отвечают 404, редактор и справочник сотрудников — только методисту,
  рейтинг отдаёт лишь отображаемые поля.
- Клиент не получает эффекты, условия и объяснения до финала; скрытый вариант нельзя выполнить по id.
- Секреты — из окружения (`.env.example`), в репозитории их нет; в логах нет паролей и токенов; CORS выключен
  (один origin через прокси); nginx добавляет `X-Frame-Options` и `X-Content-Type-Options`.

## Ограничения

- **Демо-вход:** общий пароль для всех демо-аккаунтов, нет регистрации, восстановления пароля и двухфакторной
  аутентификации. Блокировка после неверных паролей работает по логину (ответ 429 показывает, что логин существует).
  Для HTTPS нужно включить `COOKIE_SECURE=true`.
- Уведомления только внутренние; челленджей и сгорания баллов пока нет.
- Первая помощь оценивается пока в одном сценарии; для надёжной оценки нужно больше медицинских ситуаций.
- Каталог достижений и уровни заданы в коде (`app/gamification/rules.py`), условия достижений — в данных сценария.
- Интеграционный API только читает данные и защищён одним общим ключом; ротация ключей и журнал обращений — в плане.

## План развития

1. Новые сценарии по остальным ситуациям кейса (алкоголь, бесхозная вещь, потерявшийся ребёнок, маломобильные пассажиры); сверка текстов с утверждёнными регламентами.
2. SSO компании вместо демо-входа, ограничение частоты входа, аудит действий методиста.
3. Стандарт xAPI для LMS, веб-хуки о завершении обучения, несколько ключей интеграции с ротацией.
4. Челленджи недели, сгорающие баллы, push и почтовые уведомления.
5. Аналитика для руководителя бригады: слабые компетенции команды, частые ошибки по узлам.
6. Визуальная схема графа в редакторе и предпросмотр сценария методистом.
