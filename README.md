# Геймификация для ВСМ — Backend

Бэкенд обучающего приложения для проводников ВСМ-400: движок нелинейных сценариев
с таймерами, двойная шкала «лояльность пассажира» / «рейтинг безопасности»,
хранение попыток и истории решений.

Данные синтетические, реальных ПДН пассажиров и сотрудников в репозитории нет.

## Архитектура

```
frontend (React, отдельная команда)
        │  HTTP/JSON
        ▼
backend/app
 ├── api/          — FastAPI-роуты (employees, scenarios, attempts)
 ├── scenarios/     — движок сценариев: validator.py, engine.py
 ├── models/        — SQLAlchemy-модели (Employee, Scenario, Attempt, ChoiceLog)
 ├── schemas/       — Pydantic-схемы запросов/ответов
 └── core/          — конфиг, подключение к БД
        │
        ▼
   PostgreSQL (JSON-граф сценария в scenarios.graph)
```

Модульность: движок сценариев (`app/scenarios/engine.py`) не знает про FastAPI/HTTP
и не знает про конкретный сценарий — весь контент задаётся JSON-графом
(см. [docs/scenario-format.md](docs/scenario-format.md)). Новый сценарий добавляется
через `POST /scenarios` без изменения кода движка.

### Последовательность одного шага (`POST /attempts/{id}/choice`)

```
Клиент → API: choice_id (или пусто, если время вышло)
API → Engine: apply_choice(attempt, choice_id, now)
Engine: сверяет now с node_shown_at узла → если время вышло, берёт node.timeout,
        иначе — выбранный choice
Engine: применяет effects к loyalty/safety (клампит 0..100), переходит на next_node
Engine: если next_node финальный — attempt.status = finished, пишет ending_summary
API → DB: сохраняет обновлённый Attempt + ChoiceLog (аудит решения)
API → Клиент: новое состояние попытки (узел, шкалы, статус)
```

## Локальный запуск

### Через Docker (рекомендуется)

```bash
docker compose up --build
```

API поднимется на `http://localhost:8000`, автоматически создаст таблицы и
засеет один демо-сценарий и одного тестового сотрудника (`app/seed.py`).
Интерактивная документация API (Swagger UI): `http://localhost:8000/docs`.

### Без Docker

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# нужен запущенный PostgreSQL, доступный по DATABASE_URL
export DATABASE_URL=postgresql://vsm:vsm@localhost:5432/vsm

python -m app.seed
uvicorn app.main:app --reload
```

### Тесты

```bash
cd backend
source .venv/bin/activate
python -m pytest -v
```

Тесты движка (`tests/test_engine.py`) не требуют БД. API-тесты (`tests/test_api.py`)
поднимают FastAPI поверх SQLite in-memory через `TestClient` — быстрая проверка
всего HTTP-контракта без внешних зависимостей.

## API (кратко)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/employees` | создать сотрудника |
| GET | `/employees` | список сотрудников |
| POST | `/scenarios` | создать сценарий (валидирует граф) |
| GET | `/scenarios` | список сценариев |
| POST | `/attempts` | начать попытку прохождения сценария → первый узел |
| GET | `/attempts/{id}` | текущее состояние попытки |
| POST | `/attempts/{id}/choice` | отправить выбор (или пусто — таймаут) → следующий узел |

Полная спецификация — автогенерируемый OpenAPI/Swagger на `/docs` и `/openapi.json`
запущенного сервиса.

## Пример пользовательского сценария (User Flow)

1. Проводник открывает тренажёр, выбирает сценарий «Конфликт из-за откинутого кресла».
2. `POST /attempts` создаёт попытку, возвращает первый узел с текстом ситуации,
   таймером (20 сек) и тремя вариантами действия.
3. Фронтенд показывает таймер. Проводник выбирает вариант или не успевает —
   `POST /attempts/{id}/choice` с `choice_id` или пустым телом.
4. Backend применяет эффекты к шкалам лояльности/безопасности, возвращает
   следующий узел. Если это финал — `is_ending: true` и `ending_summary`
   с разбором последствий.
5. Фронтенд показывает итог, шкалы, разбор; данные попытки сохранены в БД
   для профиля, аналитики и рейтинга (следующий слой поверх этого MVP-среза).

## Ограничения текущей версии и план развития

Реализован узкий end-to-end срез: движок сценариев, таймеры, две шкалы, один
демо-сценарий, сохранение попытки. Не реализовано (следующий слой, не меняет
ядро — только новые таблицы/роуты поверх `engine.py`): профиль/уровни/опыт,
достижения, таблица лидеров, уведомления, агрегированная аналитика по
компетенциям, авторизация, `condition` на выборах (формат уже поддерживает,
движок — частично), Alembic-миграции (сейчас `create_all` при старте).

## Безопасность и данные

- В демо используются только синтетические данные (см. `app/seed.py`,
  `app/scenarios/demo_scenario.py`) — реальных ПДН пассажиров/сотрудников нет.
- Секретов и ключей в репозитории нет; `DATABASE_URL` берётся из окружения.
